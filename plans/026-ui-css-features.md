# Plan 026: UI/CSS features (orchestrated)

## Context
This plan builds the 28-item UI/CSS idea list from the review of `j3c doc css`, `j3c doc j3ui` and plan 023, in order, through `/orchestrate`. Each chunk is one subagent run. After the snapshot, the agent drift-checks the live docs and code first, and skips or trims any part that already exists. On approval, the first step copies this file to `plans/026-ui-css-features.md` and adds a row to `plans/README.md`. Progress is tracked with `- [x]` there.

**Rules for every chunk** (from AGENTS.md and j3c/AGENTS.md):
- No crates, no second parser.
- Runtime code goes in `j3c/stdlib/j3/ui/` (parse in `csslex`/`cssvalue`/`cssprop`/`cssparse`, matching in `cssmatch`, layout and paint in `ui/dom*`). Compiler code goes in `j3c/src/ui/`.
- Tests go next to the existing ones: `j3c/src/ui/tests.rs`, `j3c/stdlib/tests/*_test.j3`, and a `speculative/NN_ui_*` golden fixture where the feature is visual.
- Anything a user can see gets documented in `j3c doc css` / `j3c doc j3ui` (`j3c/src/doc.rs` or wherever the doc text lives), including the "Differences from a browser" list.
- Run `./build.sh` after stdlib edits.
- Everything runs headless: `--headless`, `SDL_VIDEODRIVER=offscreen`, `timeout`.
- `J3_STEADY=60:120` must stay at zero for idle frames.
- Existing goldens (`j3c golden examples/desk-app`, `examples/idle-breakout`) must still pass.

**Model choice:** nearly every chunk is Sonnet. The work is CSS parsing, layout and invalidation in J3, which is a niche language, so mistakes are subtle. Haiku only gets the parts that are mechanical and copy an existing pattern.
