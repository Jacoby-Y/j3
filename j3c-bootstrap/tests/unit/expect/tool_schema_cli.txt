MCP tools (`j3c -e mcp`), from the definitions `tools/list` sends. * marks a required argument.

scene_list — List scene objects
    CLI: j3c -e scene list
    Start here to learn what a scene holds (filter with a glob; group_by prefix counts names like DecoCorn). List every object in a scene: #id, Parent/Child path, kind (group, mesh, camera, light, instance), asset, world position, rotation (degrees), scale, script. Objects placed by an instance (another scene file) are not listed; edit that scene instead.
    scene: string — Scene file, e.g. scenes/main.j3scene. Default: the scene in j3.editor.toml.
    filter: string — Only objects whose id, path, or kind contains this text; with * or ? a glob on name or path (DecoCorn*).
    group_by: string (prefix) — Count objects by name with trailing digits dropped instead of listing them.
    tree: boolean — Print the objects as the scene file writes them: one line each, indent is depth, `Name kind key=value #id`. scene_apply takes those lines back.

scene_get — Get an object
    CLI: j3c -e scene get <object>|@scene
    One object as the scene file writes it (its line, then its children's, indented; scene_apply takes the lines back), then all its fields including its script's props (param.<prop>). Pass node "@scene" for scene lighting (sun, sky, fog, shadows, URP).
    node*: string — Name, Parent/Child path, #id, or @scene.
    scene: string

scene_add — Add an object
    CLI: j3c -e scene add <kind> key=value ...
    Add one object and return its #id and path. For more than a few, use scene_add_many, or place for rings, walls, stairs, grids and scatter. Shapes (cube, sphere, cylinder, cone, capsule, torus, quad, plane, sky) are meshes with that built-in asset. Top-level meshes rest on y=0 unless pos is given; names are made unique. For a mesh file use kind mesh with fields.asset; to place another scene use kind instance with fields.scene.
    kind*: string (group|mesh|camera|light|instance|cube|sphere|cylinder|cone|capsule|torus|quad|plane|sky)
    name: string
    parent: string — Parent object (name, path, or #id); default top level.
    fields: object — Same keys as scene_set, e.g. {"pos":[0,1,0],"scale":2,"material":"assets/materials/wood.j3mat"}.
    scene: string

scene_add_many — Add several objects
    CLI: none; MCP only
    Use this (or place) instead of many scene_add calls. Add several objects in one step (one file write, or one undo step in the editor). Each item is a scene_add argument object. All or nothing: if one fails, none are added.
    adds*: array of object
        kind*: string
        name: string
        parent: string
        fields: object
    scene: string

scene_apply — Write objects as scene lines
    CLI: j3c -e scene apply FILE|-
    Add or replace objects written the way the scene file writes them, which is what scene_get and scene_list tree print: `Name kind key=value ... #id`, two spaces of indent per level of nesting, `//` lines above an object are its note. Kinds: group, mesh [path], place <scene>, light, camera, or a shape (cube sphere cylinder cone capsule torus quad plane sky). Keys: pos rot (degrees) scale (one number or three) tint color range fov near far material (grain means assets/materials/grain.j3mat) texture fx alpha opacity doubleSided script tags param.<prop>=value prop.<name>=value. Numbers with a . are floats, "text" is a string, #7 is an object. A line whose #id is an object in the scene replaces that object: fields it leaves out go back to their defaults (use scene_set to change one field). A line without #id, or with an unused one, adds an object with a new id; objects it nests keep their place under it, and #refs between new lines follow. Top-level lines go under parent. One undo step; all or nothing. Use it to add many varied objects at once, copy a subtree (get it, edit the lines, drop the ids), or rewrite one object whole.
    lines*: string — The object lines, separated by newlines.
    parent: string — Object to put the top-level lines under (name, path, or #id); default top level.
    scene: string

scene_split — Move objects into their own scene file
    CLI: j3c -e scene split <object> ... out=FILE
    Move top-level objects, and everything under them, into a new scene file out (project-relative, must not exist yet), keeping their params. With center the new file is centred on the objects' middle (x, z); with instance a placed copy of the new file is left where they were, so the world looks the same and the part can be edited or reused on its own. Use it to break a big scene into regions or to make a reusable piece (a house, a tree); a game can load several files into one world with scene3d.loadParts. Objects inside another object must be moved to the top level first (scene_set parent "").
    node: string — Object to move (name, path, #id, or a glob).
    nodes: array of string
    out*: string — New scene file, e.g. scenes/biomes/forest.j3scene.
    instance: boolean = false
    center: boolean = false
    scene: string

scene_inline — Turn a placed scene into real objects
    CLI: j3c -e scene inline <instance>
    Replace a placed scene (an instance object) with real copies of its objects, so they can be edited in this scene. Per-copy values and the placement's tint are kept; scenes the placed scene places stay placed. The instance becomes a group.
    node*: string — The instance object.
    scene: string

scene_fmt — Rewrite a scene file in the canonical layout
    CLI: j3c -e scene fmt
    Rewrite the scene file in the canonical layout: tree order, defaults left out, numbers trimmed. Only needed after the file was edited by hand; the tools always write it this way. Fails (changing nothing) when the file has a line it can't read, naming the line.
    scene: string

scene_set — Change an object
    CLI: j3c -e scene set <object> key=value ...
    Set fields on an object (all or nothing). node may be a glob (DecoCorn*, *Tree?) to set every matching object; preview with scene_list filter. Keys: name; pos [x,y,z] (local to parent), x, y, z; rot [x,y,z] degrees; scale [x,y,z] or one number; parent ("" for top level; keeps local transform); asset (mesh file or builtin:cube|sphere|cylinder|cone|capsule|torus|quad|plane|sky); texture; material (.j3mat); scene (instance's scene file); script (a .j3s path, "" for none); tags (comma-separated, e.g. "nocollide,launch=30"; the game reads them with scene3d.hasTag/tagValue); param.<prop> (a prop of the object's script, typed by its props block); tint [r,g,b] or one number (meshes and placed scenes; multiplies color, 1 unchanged, above 1 allowed, e.g. [0.7,1,1.8] turns green teal); color [r,g,b] 0-1 and range (lights); fov, near, far (cameras); effects (cameras: kind=camera .j3fx files run in order, "a.j3fx|b.j3fx"; "" for none) and fx.<file stem>.<param> (their params); alpha opaque|cutout|blend; opacity; doubleSided; prop.<name> (on an instance: a prop its scene declares; "" goes back to the default). With node "@scene": prop.<name> = "<type>:<default>" declares a prop on this scene (type int, float, text, bool, material, mesh, scene; "" removes it), and sun [x,y,z] (direction toward the sun), sunColor, sky, fogStart, fogEnd, shadows, shadowSize, urp, urpBounces, urpSamples, urpShadows, urpShadowNear (meters traced sun shadows reach; the shadow map covers the rest; 0 no limit). save: true also saves the scene in the open editor.
    node*: string — Name, Parent/Child path, #id, or @scene.
    fields: object
    save: boolean — With the editor open, save the scene after the change (without it, edits stay unsaved in the editor).
    scene: string

scene_delete — Delete objects
    CLI: j3c -e scene delete <object> ...
    Delete objects and everything under them. A node may be a glob (DecoCorn*) for every match; preview with scene_list filter.
    node: string
    nodes: array of string
    scene: string

place — Place objects
    CLI: j3c -e scene ground|ontop|scatter|ring|stairs|spiral|wall ... (grid is MCP only)
    Use for anything repeated or resting on something, instead of computing coordinates by hand. Placement without coordinates. ground: drop or lift node so its lowest point rests on the surface below it (or on target only; y=0 if nothing is below). ontop: center node over target and rest it on target's top. scatter: add count copies of what (a shape like cube or cylinder, a .j3mesh or builtin: asset, or a .j3scene placed as instances) at random spots in area [x0,z0,x1,z1] (in parent's space) under a new Scatter group, each grounded, with random yaw and a scale between scale[0] and scale[1]; the same seed gives the same layout. grid: add pieces (walls, floors, roof parts) on a grid in one step: each piece's what (a .j3scene, .j3mesh, builtin: asset, or shape) goes at [x*cell, floor*height, z*cell] turned turn*90 degrees about y, under parent. ring, stairs, spiral, wall build a shape from copies of what (default cube; size is scale, builtin shapes are 1 m) in one step, named name, under parent; angles are degrees. ring: count pieces at radius around center [x,z] (arc [a0,a1] for part of a circle), bottoms at y; face tangent (default: slabs whose local x points outward, widened so the ring has no slits when size z is 0), out or in (local +z faces out or in). stairs: steps from [x,y,z] along dir (x, -x, z, -z), each rise higher and run long, width wide; solid fills to the floor. spiral: floating slabs at radius around center, each turn degrees further and rise higher (keep rise*360/turn above about 2.5 m headroom), thickness thick, width radial, depth tangential. wall: a run from [x,z] to [x,z], height high and thickness thick, with door [width,height,at] cut at meters along it (lintel over it).
    op*: string (ground|ontop|scatter|grid|ring|stairs|spiral|wall)
    node: string — Object to move (ground, ontop).
    target: string — ontop: object to put node on. ground: rest only on this object.
    what: string — scatter: shape, mesh asset, or scene file.
    area: array of number — scatter: x0, z0, x1, z1.
    count: integer = 10
    seed: integer = 1
    scale: array of number
    yaw: boolean = true
    spacing: number — scatter: least distance between copies.
    parent: string
    name: string — scatter: base name of the copies.
    ground: boolean = true
    cell: number = 1 — grid: cell size.
    height: number — grid: floor height (default cell). wall: its height (default 3).
    center: array of number — ring, spiral: [x,z].
    radius: number — ring, spiral.
    y: number — ring, spiral, wall: base height.
    size: array of number — ring: piece scale [radial, height, tangential]; tangential 0 fits the ring.
    face: string (tangent|out|in)
    arc: array of number — ring: from and to angle, degrees.
    from: array of number — stairs: [x,y,z] of the bottom edge's middle. wall: [x,z].
    to: array of number — wall: [x,z].
    dir: string (x|-x|z|-z)
    steps: integer
    rise: number = 0.4
    run: number = 1
    width: number — stairs (default 2.5), spiral slab radial size (default 2).
    solid: boolean = true
    turn: number = 20 — spiral: degrees per step.
    start: number = 0 — spiral: first step's angle, degrees.
    thickness: number — spiral slab (default 0.6), wall (default 1.5).
    depth: number = 1.2 — spiral: slab size along the turn.
    door: array of number — wall: [width, height, at].
    pieces: array of object
        what*: string
        x: number
        z: number
        floor: number
        turn: integer — Quarter turns about y.
        name: string
    scene: string

undo — Undo the last change
    CLI: j3c -e scene undo
    Put a scene file back as it was before the last change made through these tools (keeps 20 per scene). Only when the editor is closed; with it open, the person uses Ctrl+Z.
    scene: string

render — Render the scene
    CLI: j3c -e render
    Look at what you built; do this after every few edits, and from where the player would stand (at) for rooms, doors, stairs and jumps. Draw the scene as the game would (lights, shadows, sky, URP) and return the image. Default: through the main camera, or an overview if there is none. view frames all objects from a side; focus frames one object (with view's side); select outlines an object in orange. at looks from any spot (no camera object needed): yaw and pitch are degrees like a camera's rot y and x (yaw 0 looks toward -z, 90 toward -x, 180 toward +z, -90 toward +x; pitch above 0 looks up). views puts several such views in one image, two per row, width x height each. hide leaves out objects by name glob (Roof*) to see inside. ambient lifts dark interiors (default 0.25 with at/views). ortho with view top gives a true plan. With the editor open it renders the live, unsaved scene.
    scene: string
    camera: string — Camera object to look through.
    view: string (iso|front|back|side|top)
    focus: string — Object to frame.
    select: string — Object to outline.
    at: array of number — Eye position [x,y,z] in world space.
    yaw: number = 0 — With at: degrees; 0 looks toward -z, 90 toward -x.
    pitch: number = 0 — With at: degrees; above 0 looks up.
    views: array of array — Several [x,y,z,yaw,pitch] views in one image, left to right, top to bottom.
    fov: number — Vertical field of view in degrees.
    hide: string — Comma-separated name globs to leave out with their children, e.g. "Roof*,Ceiling".
    ambient: number — 0 to 1: white mixed into the ambient light; render only.
    ortho: boolean — view/focus without perspective.
    width: integer = 640
    height: integer = 360

check — Check scenes and code
    CLI: j3c -e scene check --all, then j3c check
    Run before play and before saying you are done; it names the object at fault, and runs the project's own rules (tools/check.j3s) too. Find problems before playing: broken parents, missing mesh/material/texture/scene files, placement cycles, missing scripts, object fields pointing at deleted objects, same-named siblings, and J3 compile errors (with file and line).
    scene: string — One scene; default every scene under scenes/.
    code: boolean = true — Also typecheck the project's code.

play — Play the game
    CLI: j3c run --frames N --screenshot F.png --headless
    Build the game and run it without a window for some frames (scripts run), then return the last frame as an image with the game's output. For a 3D game the output ends with a J3STATS line: average fps, draw calls, triangles, and CPU/GPU milliseconds. Build errors come back instead of an image.
    scene: string — Scene to start in; default the project's main scene.
    frames: integer = 120 — Frames to run (60 per second).
    timeout: integer = 60 — Seconds before the run is stopped.

console — Game output
    CLI: none; MCP only
    Recent game and build output: the editor's console while the editor is open, else the last play run.
    lines: integer = 50

import — Import a model
    CLI: none; MCP only
    Import .gltf, .glb, or .j3mesh files into assets/ as reusable scenes (assets/imported/<name>.j3scene), one line back per model. path may be a folder (its models, not recursive) or contain * wildcards; paths takes a list. Only a single imported model is placed (unless place is false).
    path: string — Model file, folder, or wildcard like kit/wall*.glb, absolute or relative to the project.
    paths: array of string
    bake: boolean = false — Sample each textured triangle's texture at its UV center into vertex colors and drop the texture (for palette kits like Kenney's).
    place: boolean = true
    again: boolean = false — Import even when assets/imported/<name>.j3scene exists (makes <name>_2). By default that model is skipped and the existing scene is used.
    scene: string
    name: string
    parent: string
    pos: array of number

asset_search — Find assets
    CLI: none; MCP only
    Find meshes, models, materials, images, scenes, sounds, and scripts in the project, plus the built-in shapes. Paths are what asset, material, texture, scene, and script fields take.
    query: string
    kind: string (any|mesh|model|material|image|scene|sound|font|script|code|file)

asset_online_search — Search online assets
    CLI: none; MCP only
    Search free CC0 assets online: Poly Haven models and skies, ambientCG materials, and Kenney model packs (a pack is a zip of many low-poly models). One line per result: source, id, kind, name, author. Then asset_fetch with the source and id.
    query: string — Words to match, like chair, brick, or town. Empty lists everything (up to 40).
    source: string (any|polyhaven|ambientcg|kenney) = "any"
    kind: string (any|model|material|sky) = "any"

asset_fetch — Download an online asset
    CLI: none; MCP only
    Download an asset asset_online_search found (cached in ~/.cache/j3/assets) and add it to the project, with a line in assets/CREDITS.txt. A Poly Haven model is imported like the import tool (and placed unless place is false). An ambientCG material becomes assets/materials/<id>.j3mat with its color texture. A Poly Haven sky becomes assets/skies/<id>.png for a builtin:sky mesh's texture. A Kenney pack without file lists its models; with file (a name from that list, with or without .glb) it imports that one. Kenney models look best with bake:true.
    source*: string (polyhaven|ambientcg|kenney)
    id*: string
    file: string — Kenney only: the model in the pack to import.
    bake: boolean = false
    place: boolean = true
    again: boolean = false
    scene: string
    name: string
    parent: string
    pos: array of number

gen — Run mesh generators
    CLI: j3c -e gen [--force]
    Run the project's mesh generator scripts: each assets/gen/<name>.j3 builds a mesh in code with j3.gfx.meshgen (box, cylinder, cone, frustum, sphere, capsule, torus, lathe, extrude, heightField, tri, quad; color, glow; at, turn, size, push, pop) and ends with b.save(meshgen.output("assets/gen/<name>.j3mesh")). Write the script with your file tools, then run this; use the .j3mesh as a mesh asset. Unchanged scripts are skipped unless force. Render and play run it too. `j3c doc j3.gfx.meshgen` has the API.
    force: boolean = false

scene_stats — Scene draw cost
    CLI: j3c -e scene stats [--all]
    Run after adding many objects or tints; slow scenes are usually too many distinct looks. How much a scene costs to draw: objects (placed scenes included), meshes, distinct looks (mesh, material, texture, tint: one instanced draw call each per pass), the ten biggest looks, and cutout/blended meshes that draw one by one. Above 60 looks frame time suffers; snap tints to a small palette.
    scene: string

scene_diff — What changed in a scene
    CLI: j3c -e scene diff [OLD]
    Review your own work before finishing. Objects added, removed, moved (over 1 cm, with positions), and changed (field old -> new) in a scene file since git HEAD, or since another scene file (against). Matched by Parent/Child path, so renumbered ids don't matter. Reads saved files, not unsaved editor changes. Use it to review your own edits.
    scene: string
    against: string — Project-relative .j3scene to compare with; default the scene at git HEAD.
