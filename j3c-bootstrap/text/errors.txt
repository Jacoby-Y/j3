# Error codes (plan 11 B3/B10). Read by base/diag (`title`, `explain`, embedded) and `j3c explain`.
# A code is forever: never renumber, never reuse a retired one (mark it `(retired)` in its title).
# Format: a header line `E0042: short title` starts an entry (code `E` + 4 digits, ascending, no gaps
# needed); every following line up to the next header is the long explanation, kept verbatim with its
# leading two spaces stripped. Lines starting `#` are comments. Stages add codes when they are ported.
# A code names a kind of error, not one message: sites that say the same thing in other words share it.
# Blocks by stage (a stage that runs out takes the next free hundred, listed here):
#   E0001-E0099 driver, backend, project    E0100-E0199 lexer (j3c/src/parse/lex.rs)
#   E0200-E0299 parser (j3c/src/parse/parser/, parse/mod.rs)
#   E0300-E0399 `extend` merge (j3c/src/parse/extend.rs)
#   E0400 and up: sema, lower, ... (not ported yet; each adds its block when it is)
E0001: unknown backend
  `[emit] backend` or `--emit` names a backend j3c does not have. The backends are `llvm` (native
  builds) and `bc` (`.j3s` scripts).
E0002: the C backend was removed
  j3c no longer has a C backend (plan 11 B8a): every native build goes through LLVM text and clang.
  Drop `backend = "c"` from `[emit]` or `--emit c` from the command line.
# Lexer.
E0100: unexpected character
  A character that starts no token: not an identifier, number, string, char, operator or punctuation
  (a lone `'` that is neither a char literal nor a loop label lands here too).
E0101: unterminated interpolation
  A backtick string runs to the end of the file. Close it with another backtick.
E0102: newline in interpolation
  A backtick string ends at the end of its line. Write `\n` for a newline inside it, or build the
  text with `j3.text.Text`.
E0103: invalid binary literal
  `0b` must be followed by binary digits (`0b1010`, `_` allowed between them).
E0104: invalid hex literal
  `0x` must be followed by hex digits (`0xff`, `_` allowed between them).
E0105: malformed float exponent
  An exponent needs digits after `e` and its sign: `1e9`, `2.5e-3`.
E0106: unterminated string
  A `"` string runs to the end of the file. Close it with `"`.
E0107: unterminated string escape
  A `\` at the very end of the file, inside a string.
E0108: unknown string escape
  Strings take `\n`, `\r`, `\t`, `\0`, `\\` and `\"`; anything else after `\` is an error.
E0109: newline in string
  A `"` string ends at the end of its line. Write `\n`, or join two strings.
E0110: string is not UTF-8
  A string literal's bytes are not valid UTF-8. Every `string` is UTF-8.
E0111: char literal holds more than one character
  `'ab'` is two characters. A char literal is one code point (`'a'`, `'\n'`, `'\u{1F600}'`); a string
  is `"ab"`.
E0112: empty char literal
  `''` holds nothing. Write the character between the quotes.
E0113: bad `\x` escape
  `\x` takes exactly two hex digits and is ASCII only (up to `\x7f`); write `\u{..}` for a code point
  above that.
E0114: bad `\u{..}` escape
  `\u` takes `{`, 1 to 6 hex digits and `}`, and the value must be a Unicode scalar value (not a
  surrogate, at most `10FFFF`).
E0115: unknown char escape
  Char literals take `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`, `\x..` and `\u{..}`.
# Parser.
E0200: expected a token
  The parser needed one particular token here (`;`, `}`, `)`, a keyword, a string, ...); the message
  names it. Usually something just before this point is missing or misspelled.
E0201: expected identifier
  A name was needed here (a variable, field, function, type or module name). Keywords are not names.
E0202: expected expression
  A value was needed here: a literal, a name, a call, an operator expression, a block.
E0203: expected an item
  Module scope holds `use`, `const`, `fn`, `struct`, `enum`, `trait`, `extend` and `#[singleton]
  let`; statements go inside a function.
E0204: control flow at module scope
  `if`, `while`, `for`, `match` and the like run inside a function body, not at module scope.
E0205: misplaced doc comment
  A `///` doc comment documents the next fn, struct, enum, const, let, field or variant; nothing of
  that kind follows it here. Use `//` for a plain comment.
E0206: attribute takes no arguments
  `#[Debug]`, `#[singleton]`, `#[thread]`, `#[impl]` and the shader markers are written bare.
E0207: unknown attribute
  The name inside `#[..]` is not an attribute j3c knows (`j3c doc lang` lists them).
E0208: cannot derive this trait
  `#[derive(..)]` takes only the derivable traits the message lists.
E0209: trait derived twice
  A trait appears twice in one `#[derive(..)]` list. Drop one.
E0210: attribute on the wrong item
  The attribute does not fit the item under it (`#[impl]` marks a free fn, `#[derive]` a struct or
  enum, `#[uniform]` a module `let`, ...); the message says where it goes.
E0211: `#[singleton]` mixed with other attributes
  A singleton `let` takes no `#[Debug]`, `#[TryCatch]` or `#[impl]`.
E0212: module `let` without `#[singleton]`
  Module-scope state is a `#[singleton] let`; a plain constant is `const`.
E0213: `pub` on a singleton
  A singleton `let` is reached through its module already; drop `pub`.
E0214: `#[uniform]` with an initializer
  A shader uniform has no value in the source: the CPU sets it by name at draw time.
E0215: `pub use` is not valid
  Imports are private to the module that writes them; a module cannot re-export with `pub use` or
  `pub use lib`.
E0216: `pub extend` is not valid
  Methods in an `extend` block are public like those in a struct body; drop `pub`.
E0217: empty use path
  `use` needs a module path (`use j3.io.printLn;`).
E0218: bad `#[shader]` or `#[vertex]` argument
  `#[shader(..)]` takes `vertex` or `fragment` (a helper is plain `#[shader]`); `#[vertex(..)]` takes
  `instance`.
E0219: unknown field attribute
  A struct field takes `#[flat]` (on a `#[varying]` struct field) and nothing else.
E0220: one-element tuple
  A tuple (value, type or pattern) has two or more elements. `(x)` is just `x` in parentheses.
E0221: range pattern without its end
  Range patterns include their end: write `a..=b`, not `a..b`.
E0222: expected an integer or char pattern
  A range pattern's ends are integer or char literals.
E0223: label not on a loop
  A `'label:` goes right before `while` or `for`.
E0224: integer literal too large
  The literal does not fit 64 bits (decimal, hex or binary).
E0225: invalid float literal
  The digits do not form a float j3c can read.
E0226: bad array length
  An array type is `[N]T` with an integer literal `N` that fits in memory, or `[]T` for a slice.
E0227: unterminated interpolation hole
  A `{` in a backtick string has no matching `}`. Write `{{` for a literal brace.
E0228: empty interpolation hole
  `{}` in a backtick string holds no expression. Write `{{}}` for literal braces.
E0229: trailing text in interpolation hole
  A hole holds one expression; something follows it before the `}`.
E0230: if-expression without `else`
  An `if` used as a value needs an `else` branch, so it has a value either way.
E0231: bad atomic intrinsic arguments
  `@atomic..` intrinsics take a pointer, the operation's values, then an optional memory order.
E0232: bad memory order
  The memory order is not one this atomic operation accepts; the message lists them.
E0233: unknown intrinsic
  The name after `@` is not an intrinsic j3c knows.
E0234: bad `@slice` arguments
  `@slice(ptr, len)` takes a pointer and a length.
E0235: bad `@script` path
  `@script` takes a string literal naming a `.j3s` file.
E0236: bad `@embed` argument
  `@embed`, `@embedDir` and friends take non-empty string literals (paths relative to the file).
E0237: expected `{ ptr, len }`
  A slice built from parts is `[]T { ptr, len }`.
E0238: turbofish without a call
  `name::<T>` gives type arguments to a call: write `name::<T>(..)`.
E0239: expected an overloadable operator
  `fn operator..` takes one of the operators the message lists.
E0240: method declared outside its struct
  Methods go in the struct body (`struct T { fn name(this: &T) { .. } }`) or an `extend T` block,
  never as `fn T.name(`.
E0241: named function where a closure goes
  `fn` in an expression starts a closure: `fn(x: int): int { .. }`. Named functions are declared at
  module scope.
E0242: bound listed twice
  The same bound (or the same type parameter in `where`) appears twice; join bounds with `+`.
E0243: type parameters on a trait
  Traits and trait methods take no type parameters.
E0244: bounds on `extend`
  Bounds belong on the struct's type parameters, not on its `extend` block.
E0245: `pub` in an `extend` body
  Methods in `extend` are public already; drop `pub`.
E0246: not allowed in a script
  `.j3s` scripts take no `module` line, `use lib`, `extend`, or `trait`, and only `use`, `const`,
  `props`, `shared`, `let`, `fn`, `struct` and `enum` at top level.
E0247: bad `@j3ui` function
  An `@j3ui` function takes a `Ui` receiver as its first parameter, its widgets sit inside a
  component, and only container widgets take a body.
# `extend` merge.
E0300: `extend` on an enum
  Only structs take methods. Write a free fn `fn m(this: E)`; it calls as `x.m()`.
E0301: `extend` outside the struct's module
  Methods of a struct go in its own module: its file or one of its part files.
E0302: `extend` names no struct
  No struct of that name is declared in this module. Declare it, or fix the name.
E0303: `extend` type parameters differ
  The `extend` block names the struct's type parameters exactly as the struct does.
E0304: method defined twice
  A method is written once, in the struct body or in one `extend` block; rename one.
