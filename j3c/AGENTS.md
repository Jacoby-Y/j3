# j3c — agent map

J3 compiler crate. The contract is this file, `../roadmap.md`'s non-goals, and `../speculative/` (01–08 run, 09 typechecks, `10_j3ui.j3` typechecks). If this file and those disagree with an example, the example's test in `compile.rs` is what `cargo test` locks.

Host: Rust, no crates.io deps. **Emit is LLVM by default** (text `.ll` + host `clang`). C is optional (`--emit c` or `[emit] backend = c`). Script bytecode is a third printer over the same checked IR. The runtime bytecode VM in J3 is allowed; the comptime interpreter remains out of scope. No libLLVM, no crates.io. `--fast` strips OOB `Abort`. `--release` ships small: opt `s`, no `-g`, stripped, and swaps `j3.build` (`build.j3`, `DEV = true`) for `build_release.j3` (`RELEASE = true`; `Loader::module_path`), per-platform link flags (`emit::host::release_flags`/`target_os`; Linux also drops unwind tables). Whole-program LLVM builds print failed checks through one `@j3_abort` (`emit/llvm.rs` `abort_routine`, packed `file<<40|line<<8|kind`), and so do ThinLTO release objects (one private routine per object); split and per-module dev builds keep a message per site. On the Linux host with `ld.lld` or `mold`, `--release` compiles one `-flto=thin` object per module (`incr::thin_lto`, `obj-thin/`, functions get `optsize`/`minsize` for `-Os`/`-Oz`) and the linker optimizes across modules with a cache (`thinlto/`); `J3C_NO_THINLTO=1` forces the one-clang path, which other targets always use. The IR with places is the backend contract.

Run from this directory (`j3c/`):

```

cargo run -- dump-c

cargo run -- run ../examples/scripted
cargo run -- run ../examples/fps-shooter/tools/arena.j3s
cargo run -- -e script-props scripts/door.j3s
cargo run -- dump-syntax ../editors/vscode/syntaxes/j3.tmLanguage.json
cargo run -- run examples/hello.j3
cargo run -- run --emit c examples/hello.j3
cargo run -- run --opt 2 examples/hello.j3
cargo run -- run samples
cargo run -- check ../examples/gallery
cargo run -- new /tmp/mygame
cargo run -- doc j3.app
cargo run -- doc lang
cargo run -- doc j3ui
cargo run -- doc css
cargo run -- doc testing
cargo run -- doc ship
cargo run -- dump-ui ../examples/idle-breakout/ui
cargo run -- -e imgdiff a.png b.png --tol 2 --max 50
cargo run -- guide
cargo run -- help manifest
cargo run -- run ../examples/gallery
cargo run -- build --fast ../examples/gallery
cargo run -- fmt examples/hello.j3
cargo run -- lsp
cargo run -- help
```

`run` / `build` / `check` with no path use `./j3.toml` and stop if it is missing (`j3c new`, `j3c guide`). `check` typechecks, then reports a missing host library and a missing file passed to `loadFont` / `tryLoadFont` / `loadTexture` / `tryLoadTexture` / `loadRgba` / `loadSound` / `tryLoadSound` / `loadMusic` / `tryLoadMusic` / `setVolume` / `setMusicVolume` / `stop` / `stopMusic`. It does not run the program. `run` uses that same check and does not launch when it fails. A cross-compile target skips the library probe. `dump-ir` with no path still parses `examples/hello.j3` + `stdlib/j3` and prints typed IR. `dump-ir samples` prints `ir/samples.rs` after `validate` (place picture). `dump-c` / `dump-llvm` with no path emit that hello; `run examples/hello.j3` executes it (`printLn("Hello, world!")`). `dump-syntax` writes the editor TextMate grammar from lexer/parser tables (shipped at `../editors/vscode/syntaxes/j3.tmLanguage.json`); `dump-syntax --ui` writes the `.j3ui` one (`j3ui.tmLanguage.json`, element names from `ui::gen::ELEMENTS`; a test keeps both in sync, and `node ../editors/vscode/check-grammars.js` checks includes and regexes). `run samples` is the place tests. `run foo.j3` compiles a real file. `run` / `build` also take a directory with `j3.toml` (`../examples/gallery`, `../examples/fps-shooter`). A project run executes the binary with **cwd = package root** (`J3_ROOT`). **Agents never open a window**: use `run --frames N --screenshot F.png --headless` (sets `SDL_VIDEODRIVER=offscreen`, `SDL_AUDIODRIVER=dummy`); a built binary needs both on the same command. `J3_CAPTURE=out.png:N` and `J3_FIXED_DT=0.016` make repeatable captures, and `j3c -e imgdiff` compares them (`j3c doc testing` is the shipped page; keep `src/doc/pages/testing.md` current when these change). `fmt` pretty-prints from the same lexer (comments stay). `lsp` is stdio JSON-RPC: hover, goto-def, scoped completion (including `use`), signature help, document symbols, import quick-fix, diagnostics, format — same parse + check, no second frontend. Diagnostics for an error in another open buffer are published on that buffer.

`/target` must stay small: no incremental, no extra crates. Host `clang -g` / `cc -g` is on unless `--fast`. Flags live in `Cargo.toml` and `.cargo/config.toml`. Do not add clap, serde, inkwell, llvm-sys, or anyhow.

## Pipeline

```
parse  →  check  →  ir  →  emit LLVM (default), C, or script bytecode
LIVE      LIVE      LIVE    LIVE
```

`SSL_set1_host` plus `SSL_VERIFY_PEER` always on, SNI through `SSL_ctrl` 55, min TLS 1.2 through `SSL_CTX_ctrl` 123, `SSL_OP_IGNORE_UNEXPECTED_EOF`; `lastError` is per thread) and `j3.net.http` (`Request`/`open` → `Stream` with Content-Length, chunked, or close framing, 1xx skipped, redirects drop `Authorization`/`Cookie` off-host, CR/LF in a header is `BadRequest`; `LoadLibraryA` on Windows). `j3.proc` builds argv and envp before `fork` so the child only makes raw calls, reports `execve` failure through a CLOEXEC pipe, and pumps stdin/stdout/stderr with `poll` (`stdlib/tests/proc_test.j3`). `j3.data.json` is a recursive-descent parser (depth 512, numbers through libc `strtod`, written back with `snprintf("%.*g")` at the shortest of 15-17 digits that reads back; bionic has no `gcvt`. A `use lib` binding of a variadic prelude function (`snprintf`) may add fixed trailing params, and the LLVM emitter calls it with the variadic type), a shared read-only null node for misses (`json_test.j3`). Gotchas met there: a backtick string lives in the calling function's stack frame (never keep one in a struct that outlives it); `!=` on a NaN is false, so test `!(x == x)`; the C backend cannot emit `&[N]T` parameters (take `[]T`); a `match` on an enum lists every variant (a `_ {` arm is rejected). `j3.thread` is Linux pthreads: `Thread`, `Mutex`, `Cond`, `Queue<T>`, `Pool` (`parallelFor`), with `#[thread]` per-thread globals and `@atomicLoad`/`Store`/`Add`/`Cas` (`speculative/13_threads.j3`, `j3c doc recipes threads`). On Android `j3.sys.start` (`sys_android.j3`) first calls `j3.apkassets.boot`, which copies the APK's `assets/` files listed in `assets/j3assets.txt` (line 1 `j3assets 1 <stamp>`, then one relative `/` path per line; unsafe paths skipped) to `SDL_AndroidGetInternalStoragePath()` through SDL_RWops (tmp file + rename, `j3assets.stamp` written last, skipped when the stamp matches) and `chdir`s there; `j3.apkassets` only uses libc, takes its bytes from a `Source` (test: `stdlib/tests/apkassets_test.j3`), and is not linked on desktop. Window, GL, SDL, audio, and every `j3.game`/`gfx`/`scene3d`/`ui`/`app` value are main-thread only.

Do not start a second parser. The LSP lives in `src/lsp/` and calls `compile::analyze_checked`. Cranelift is not a required middle step. New printers plug into `emit::Backend` and consume the same typed IR.

The **library** (`src/lib.rs`) is what the LSP depends on. The **bin** (`src/main.rs`) only calls `cli::run`.

## Crate root

Optional `j3.gfx.urp.raytrace` is a fullscreen sphere/room path tracer with a
custom-shader hook (its README has a sample). Optional
`j3.gfx.urp.forest` routes `j3.gfx` camera color and depth through an external
framebuffer, samples the same alpha-cutout canopy shadow map for volumetric
light, and composites analytic glass and metal spheres.
Both need a GL context from `App.useGl()` and release GL resources before that
context closes. The URP entry points are in `stdlib/j3/gfx/urp/README.md`.

Scene editing that only the editor does lives in `stdlib/j3/scene3d/editor/` (`j3.scene3d.editor.overrides`, `props`, `paste`, `uses`): per-copy overrides, declaring and renaming props, pasting placed objects, and the placement loop check. Games load, draw, and read props with `j3.scene3d` alone.

Procedural 2D art lives in `stdlib/j3/gfx/canvas.j3`: RGBA8 `Canvas`, pixel/smooth modes, clipped primitives, seeded noise, and PNG export. `j3.game.textureFromCanvas` uploads it for SDL or GL; `updateTextureFromCanvas` updates a rectangle. `j3c doc recipes canvas` generates assets without SDL. Keep its hot drawing loops allocation-free and clip before iterating. The scaffolded `AGENTS.md` teaches agents to use the API and compose more readable game art.

## IR (`src/ir/`)

Every expression, statement, and binding has a concrete `Ty`. There is no `Option<Ty>`. If a pass cannot name a type, it is a compiler bug.

**Places are required now**, not in a later lowering. Field/index of `&T` name a slot (no memcpy). Auto-deref is `Proj::Deref`. `+=` is `StmtKind::AssignOp` and binds the place once. Local `use` aliases are the same `local + proj` as the field they name.

### Place samples (what `dump-ir samples` must keep showing)

- `scale`: `(*this).x *= copy s` — auto-deref preserves a place
- `bump`: `xs[copy i] += 1` — index bound once
- `tick`: `arena_ref = &(*(*g).mem)` — `&` of the Arena **header**, not a copy of it; `(*g).running = false`

If a change makes those strings go away, the IR is wrong.

`run samples` also executes `main` in that module: scale a `Vec2`, bump a slice, `tick` must clear `g.running`. Failures `_exit(1)` via `@syscall(60, …)`.

## Stdlib

Source of truth: `stdlib/j3/*.j3`, compiled into the binary with `include_str`. A copied `j3c` does not need that directory. `J3_STDLIB` replaces the embedded copy. `j3c run` parses `sys` + `io` + the entry file. `j3.sys.start` calls user `main` then `exit(0)`. mmap/Arena IR is later.

Scenes: a `.j3scene` file is one line per object, rotation in degrees (format: `editor/README.md`, "Scene file format"). `scene3d` (`parse`, `write`, `nodeText`) is the reader and writer; `src/scenefile.rs` reads both file versions for the Rust side (diff, script checks, asset renames) and `tools/j3scene_migrate.py` converts v1 files, so a rule changed in one is changed in all three (`j3c -e scene fmt` on a v1 file must match the migrator byte for byte). Old files (`node.<i>.*`, radians) still load.

## How data is owned

```
IrCx
  names, tys, structs, enums, funcs
Module
  name, ids into the cx
Func.kind = J3 { body }
  locals, params, block of Stmt
Place
  LocalId + Vec<Proj>  (not a nested tree of places)
```

Need a new interned type? `cx.intern_ty(TyKind::…)`. Need a builtin? add it in `IrCx::new` / `CommonTys`. Need a new statement? `stmt.rs` + dump arm + validate arm + a sample if it touches places.

C / LLVM names: structs are `j3_<module>_<name>_<id>` (that id is local to one compile). Function symbols are `j3_<module>_<name>_<sig>`, where the suffix hashes the signature and, for a method, its type arguments — not the allocation order, so an object cache can reuse them. Slices are `j3_sl_<elem>` (`[]int` → `j3_sl_i64`), `string` → `j3_string`. Store `module` on the IR entity so names stay stable if another module is in the same `IrCx`. Do **not** intern places or switch to CFG. Parser exists for the hello subset; grow the grammar there, not a second frontend.

`[emit]` in `j3.toml`: `backend` (`llvm` default, or `c`), `opt` (`0`/`1`/`2`/`3`/`s`/`z` — `0` compile speed, `2` runtime), `incremental` (default true: opt 0 keeps one object per module; `"all"`: every opt; dev `j3c run` of a scripted project uses it too), `debug`, `fast`, `target` (one triple or an array; `build` emits each to `target/<triple>/<name>`, `run` uses the host triple), `cpu`, `clang`, `flags`. `[dist] build_outputs = ["zip", "deb"]` (`zip = true` is `["zip"]`; + optional `include`, `icon`, `title`, `categories`, `maintainer`, `depends`): `build --release` writes each per target into `target/dist/` (`src/dist.rs`; the `.deb` in `src/dist/deb.rs` is `tar` + a hand-written `ar`, no dpkg, and installs to `/opt/<name>` with a launcher that runs from `~/.local/share/<name>`). Stamps, objects, and the dev binary live in `target/.j3c/` (`emit::host::cache_dir`). No `[emit]` inherits `[cc] opt`. CLI `--emit` / `--opt` override. If clang is missing and LLVM was not forced, fall back to C.

## Style

- Small files. A module that grows past ~1000 lines becomes a folder: `mod.rs` keeps the types, the entry points and the shared imports, and children split by concern (`check/`, `check/lower/`, `parse/parser/`, `ui/gen/`, `emit/bc/`, `lsp/complete/`, `editor/`, ...), each starting `use super::*;`. A big `impl` is split by writing `impl Foo` again in a child file. Long text lives in `.md`/`.j3` files through `include_str!`; files that hold `j3c doc`/help text are listed in `stdlib::docs_id`. No macros. Explicit matches. Named fields.
- Verbose is fine if a human can tweak it.
- Comments name the rule. Do not cite speculation.md.
- Do not introduce `Option<Ty>` “until check fills it in.” Check produces IR; IR is already typed.

## Do not build

Borrow checker, drop/RAII, trait solver, comptime interpreter, capturing closures, GC, user-defined `#[attributes]`, operand swap, Cranelift, libLLVM/inkwell.

Unknown `#[foo]` / `@foo()` will be compile errors in the parser. `@ident(...)` is only compiler **calls** (`@syscall`, `@sizeof`, `@slice`, `@atomic*`). Attributes are `#[attr]` on the next item.
